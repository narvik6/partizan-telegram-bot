# Выделенный Gmail для кодов SSO

## Владелец сервера — один раз

1. Создайте отдельный личный Gmail. Включите двухэтапную аутентификацию Google.
2. Создайте [пароль приложения](https://myaccount.google.com/apppasswords), подпись — `partizan`. Это подпись, не регистрация OAuth-клиента.
3. В Portainer задайте `MAIL_HOST=imap.gmail.com`, `MAIL_USERNAME` (полный адрес), `MAIL_PASSWORD` (пароль приложения), `SSO_MAIL_SENDER` (точный отправитель настоящего письма SSO). Обычный пароль Google не используется.
4. Обновите stack с новой версией backend. В консоли контейнера выполните `python backend.py mail-check`. Успех подтверждает IMAP, но не соответствие письма парсеру.

OAuth, Google Cloud/Azure, Client ID и браузер на сервере не нужны. Пароль приложения остаётся на сервере.

## Пользователь — пересылка и первый вход

1. В основной Gmail: «Все настройки → Пересылка и POP/IMAP → Добавить адрес пересылки». Адрес выделенного ящика показан в настройках partizan.
2. Подтвердите адрес по письму в выделенном ящике. Для общего ящика помогает его владелец.
3. Общую пересылку всей почты оставьте выключенной. Создайте фильтр по точному отправителю кодов SSO → пересылать на выделенный ящик. При необходимости уточните фильтр темой, чтобы он выбирал именно коды.
4. Запросите новый код, проверьте поступление письма. Фильтр работает для новых писем.
5. В partizan: «Настройки → Вход и автоматизация»: учебная почта `@edu.mirea.ru`, пароль SSO,  Поля сохраняются при уходе из поля.
6. Нажмите «Подключить почтовые коды», один раз введите код вручную в окне SSO, пропустите МАКС, закройте окно после входа. Приложение проверит пересланное письмо и сохранит подключение.

Помощник работает без сохранённого пароля. Приложение запрашивает только код для своего получателя, номера `#00` и времени попытки; Gmail-пароль и остальные письма ему не выдаются.
При задержке автоматический вход ждёт и ограниченно запрашивает новый код. При нераспознанном формате или неоднозначности нужна помощь.
ФИО не запрашивается. Первый введённый код связывает устройство с получателем исходного письма. Сервер проверяет DKIM-подпись отправителя, подписанные To/Date/Subject/From и свежесть; произвольным заголовкам Authentication-Results не доверяет. Если пересылка меняет подписанные данные или теряет исходного получателя, автоматическое подключение не выполняется. Настоящее письмо МИРЭА и сохранение подписи при пересылке ещё предстоит проверить.
