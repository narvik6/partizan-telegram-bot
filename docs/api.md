# API partizan backend

Один HTTPS-поддомен. Почта — `POST /`, Telegram — `POST /partizan_agent`.
`GET /health` возвращает `{"ok":true}`: это доступность процесса, а не проверка почты/Telegram.
`GET /` дополнительно возвращает публичный `forwarding_address` выделенного ящика для инструкции пересылки.

## Первое подключение почты

`POST /`, JSON без Authorization:

```json
{"action":"connect","username":"student@edu.mirea.ru","request_number":"#00","requested_at":"2026-11-19T12:00:00Z","code":"012345","device_id":"случайный_base64url_идентификатор_установки"}
```

Приложение отправляет код первого ручного SSO-входа. Сервер сверяет его с письмом по коду, номеру попытки, отправителю и времени. Получатель берётся из подписанного исходного письма.
`202 {"ok":true,"state":"pending"}` — письмо ещё не пришло, повторяется тот же запрос.
`200 {"ok":true,"connection_token":"…"}` — устройство подключено, код не возвращается.
Одна почтовая попытка подключает одно устройство; повтор того же device_id идемпотентен. Пять неверных кодов блокируют подключение по этому письму, нужен новый SSO-код.

Device ID — 32–128 символов base64url. Учебный адрес валидируется по `@edu.mirea.ru`; выбор письма — по привязанному получателю и номеру, глобальная уникальность номера не предполагается.
При смене учётной записи требуется новое подключение. Ключи вручную не выдаются.
Токен сохраняется в системном хранилище desktop; сервер хранит хеш токена, привязку к исходному получателю, seed и использованную попытку в `/data/mail-clients.json`, 0600, атомарная запись/блокировка.

## Получение кода

`POST /`, `Authorization: Bearer <connection_token>`.
JSON: ровно `request_number` и `requested_at` (ISO8601 с зоной).
Время соответствует началу текущего запроса и не старше 15 минут. `#00` сохраняет ведущие нули.

- `200 {"ok":true,"code":"012345","request_number":"#00"}` — единственное подходящее письмо.
- `202 {"ok":true,"state":"pending"}` — письмо ожидается.
- `401` — неизвестное устройство или неверный первый код.
- `400` — неверные поля/номер/время.
- `503` — почта не настроена/недоступна, формат не распознан или несколько совпадений.

Ошибки имеют машинное поле `error`. API не выдаёт списки писем, полное письмо или пароль Gmail.
IMAP: TLS, INBOX read-only, UID SEARCH, BODY.PEEK, INTERNALDATE. До 250 последних кандидатов; фильтруются время, отправитель, ФИО и номер.
Извлекается подписанный код либо единственная шестизначная последовательность. Реальный шаблон МИРЭА ещё требует сверки.
Получатель выбирается сервером из привязки, клиент не передаёт адрес, имя или фильтр. Дополнительные поля отвергаются. При одинаковом #00 для разных студентов чужое письмо исключается. Первое подключение требует знания ручного кода и однозначного подписанного получателя. Проверяются DKIM-подпись домена ожидаемого отправителя, подписанные From/To/Date/Subject и полное тело без l=. Подписанная Date свежая и соответствует попытке с допуском секундной точности. Идентичность письма вычисляется по подписи, поэтому изменение неподписанного заголовка не позволяет повторно подключить устройство. Дубли To/From/Subject/Date, отсутствие подписи/получателя, неоднозначность и недоступная проверка закрывают автоматическую выдачу. Authentication-Results из самого письма не служит доказательством. Старые привязки к имени не мигрируют в разрешения получателя; нужен первый ручной вход. Реальный шаблон и сохранность подписи пока не проверены.

## Telegram

`POST /partizan_agent`; старый `/v1/attendance` сохранён.
`Authorization: Bearer phrase.<base64url UTF-8 фразы без padding>`; NFC, нижний регистр, один пробел.
Старые длинные ASCII-коды принимаются напрямую, пока пользователь не запросит фразу через /connect.
Фраза — два случайных слова из собственного списка русских существительных `words_ru.txt`, это не копия EFF.

JSON: ровно `event_id`, `kind` (`attendance_required` или `test`), `title`, `body`.
Получатель определяется фразой. `200` — доставка или уже доставленный ID, `401` — неверная фраза, `410` — чат отключён, `502` — ошибка Telegram, `503` — Telegram выключен.
Подписки, offset и дедупликация — SQLite на постоянном томе. Один BOT_TOKEN обслуживается одной копией long polling.
Поддерживаются TELEGRAM_PROXY (HTTP/SOCKS5/SOCKS5h) и стандартные proxy env. В Portainer по умолчанию `socks5h://throne:2080`.
OTP, QR-токены и ссылки комнат не входят в сообщения.

## Контейнер и проверки

Compose сохраняет сервис `bot`, volume `bot-data` и имя образа.
Сеть `proxy` — Nginx Proxy Manager, `vpn` — Throne; алиасы `partizan-backend` и `partizan-telegram-bot`.
Git-stack Portainer обновляет и Compose, и образ; stack из веб-редактора сам Compose из Git не подхватывает.
Секреты остаются на сервере, не включаются в образ и не выводятся в HTTP-журнал.

```sh
docker build --target test -t partizan-backend:test .
docker run --rm --network none --read-only --tmpfs /tmp:size=16m partizan-backend:test
```

Письма и Telegram API в тестах фиктивные.
