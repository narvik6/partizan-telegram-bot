# API partizan backend

Один HTTPS-поддомен. Почта — `POST /`, Telegram — `POST /partizan_agent`.
`GET /health` возвращает `{"ok":true}`: это доступность процесса, а не проверка почты/Telegram.
`GET /` дополнительно возвращает публичный `forwarding_address` выделенного ящика для инструкции пересылки.

## Первое подключение почты

`POST /`, JSON без Authorization:

```json
{"action":"connect","username":"student@edu.mirea.ru","request_number":"#00","requested_at":"2026-11-19T12:00:00Z","code":"012345","device_id":"случайный_base64url_идентификатор_установки"}
```

Приложение отправляет код первого ручного SSO-входа. Сервер сверяет его с письмом по коду, номеру попытки, отправителю и времени. Получатель берётся из подписанного исходного письма.
`202 {"ok":true,"state":"pending"}` — письмо ещё не пришло, повторяется тот же запрос.
`200 {"ok":true,"connection_token":"…"}` — устройство подключено, код не возвращается.
Одна почтовая попытка подключает одно устройство; повтор того же device_id идемпотентен. Пять неверных кодов блокируют подключение по этому письму, нужен новый SSO-код.

Device ID — 32–128 символов base64url. Учебный адрес валидируется по `@edu.mirea.ru`; выбор письма — по привязанному получателю и номеру, глобальная уникальность номера не предполагается.
При смене учётной записи требуется новое подключение. Ключи вручную не выдаются.
Токен сохраняется в системном хранилище desktop; сервер хранит хеш токена, привязку к исходному получателю, seed и использованную попытку в `/data/mail-clients.json`, 0600, атомарная запись/блокировка.

## Получение кода

`POST /`, `Authorization: Bearer <connection_token>`.
JSON: ровно `request_number` и `requested_at` (ISO8601 с зоной).
Время соответствует началу текущего запроса и не старше 15 минут. `#00` сохраняет ведущие нули.

- `200 {"ok":true,"code":"012345","request_number":"#00"}` — единственное подходящее письмо.
- `202 {"ok":true,"state":"pending"}` — письмо ожидается.
- `401` — неизвестное устройство или неверный первый код.
- `400` — неверные поля/номер/время.
- `503` — почта не настроена/недоступна, формат не распознан или несколько совпадений.

Ошибки имеют машинное поле `error`. API не выдаёт списки писем, полное письмо или пароль Gmail.
IMAP: TLS, INBOX read-only, UID SEARCH, BODY.PEEK, INTERNALDATE. До 250 последних кандидатов; фильтруются время, отправитель, ФИО и номер.
Извлекается подписанный код либо единственная шестизначная последовательность. Реальный шаблон МИРЭА ещё требует сверки.
Получатель выбирается сервером из привязки, клиент не передаёт адрес, имя или фильтр. Дополнительные поля отвергаются. При одинаковом #00 для разных студентов чужое письмо исключается. Первое подключение требует знания ручного кода и однозначного подписанного получателя. Проверяются DKIM-подпись домена ожидаемого отправителя, подписанные From/To/Date/Subject и полное тело без l=. Подписанная Date свежая и соответствует попытке с допуском секундной точности. Идентичность письма вычисляется по подписи, поэтому изменение неподписанного заголовка не позволяет повторно подключить устройство. Дубли To/From/Subject/Date, отсутствие подписи/получателя, неоднозначность и недоступная проверка закрывают автоматическую выдачу. Authentication-Results из самого письма не служит доказательством. Старые привязки к имени не мигрируют в разрешения получателя; нужен первый ручной вход. Реальный шаблон и сохранность подписи пока не проверены.

## Telegram: отправитель и подписки

Подключение приложения и подписка — разные разрешения.

`POST /partizan_agent/connect`, JSON `{"phrase":"река лес","client_id":"случайный_base64url_идентификатор_32–128_символов"}`.
Фраза из двух существительных выдаётся /connect в Telegram, действует пять минут и используется один раз. Сохраняется её SHA-256, а не исходный текст.
Ответ: `{"ok":true,"token":"43_символа_base64url","publisher_code":"0123"}`.
Ключ публикации — HMAC с серверным случайным seed; он хранится только в системном хранилище клиента, на сервере — его хеш.
Повтор того же подключения с тем же client_id идемпотентен до истечения фразы. Другая установка получить доступ по использованной фразе не может.
У отправителя только одна активная привязка: успешное новое подключение отзывает предыдущий ключ. Запрос новой фразы сам по себе ещё не отключает работающий клиент.
Ограничение запросов подключения: десять в минуту на наблюдаемый сервером IP; за reverse proxy это может быть общий адрес прокси.

`POST /partizan_agent` (старый путь /v1/attendance принимает тот же новый протокол).
`Authorization: Bearer <token>`, `X-Partizan-Client: <client_id>`.
JSON содержит event_id, kind, title, body и необязательные scope/signal.
Kinds: lecture_soon, webinar_found, attendance_required, lecture_finished, login_required, stage_failed, test.
Поле scope — SHA-256 от публичных organization/event ID вебинара, без пароля доступа и параметров участника. Для напоминания до открытия — группа/дисциплина/начало.
Signal различает qr и mts. Незнакомый формат URL не получает общий scope: тогда работает только дедупликация конкретного event_id.

`/code` показывает стабильный публичный четырёхзначный код автора; ведущие нули сохраняются. Он не даёт права публикации.
`/subscribe 0123` подписывает текущий чат, `/subscriptions` показывает список, `/unsubscribe 0123` удаляет одну подписку.
Для группы настройками управляет администратор; секретная фраза отправляется ему в личный чат.
Автор получает выбранные в приложении события. Подписчикам пересылаются только lecture_soon, webinar_found, attendance_required, lecture_finished.
Авторизация, ошибки этапа и test остаются личными. Удалённых команд отметки или управления браузером API не предоставляет.
`/stop` отключает чат и его публикацию, удаляет его подписки. Коды авторов при новом подключении сохраняются.

Фан-аут использует множество получателей: владелец, также подписанный на другого автора, получает событие один раз.
Повтор event_id одного отправителя подавляется сутки. События разных отправителей с одинаковыми chat/scope/kind/signal объединяются скользящим окном 60 секунд; отличающиеся тексты не мешают объединению. Окно не продлевается подавленным повтором.
Это объединяет задержку в 10 секунд и разрешает следующий десятиминутный QR-цикл. Другой вебинар или другой тип контроля не подавляется.
Успешные доставки отмечаются отдельно по получателям; сбой одного не повторяет уже доставленное остальным. HTTP 200 подтверждает доставку либо подавленный повтор; 401 — переподключение, 410 — отправитель отключён, 502 — ошибка доставки, 503 — Telegram выключен.

Сообщение с фразой использует spoiler entity с UTF-16 offset/length. Срок удаления — пять минут или сразу после использования (исполнитель проверяет очередь каждые пять секунд).
Очередь хранится в SQLite, восстанавливается после перезапуска. Временные ошибки deleteMessage повторяются; окончательный отказ Telegram нельзя превратить в гарантию удаления. Фраза всё равно перестаёт авторизовывать после использования/срока.
Подписки, коды, привязки, дедупликация и очередь удаления хранятся в прежнем volume bot-data. Старые повторно используемые фразы/ключи больше не авторизуют публикацию: обновлённому приложению нужен /connect.
Исходящие обращения Telegram сохраняют поддержку TELEGRAM_PROXY и стандартных proxy env.

### Границы модели

Четыре цифры — публичный адрес автора, не закрытое приглашение. Если нужны закрытые подписки с одобрением владельца, это отдельное решение.
Одноразовая привязка и client_id запрещают штатное подключение второго устройства той же фразой; копирование всего уже выданного служебного ключа вместе с client_id не является аппаратно различимым событием. Аппаратная аттестация и отдельные аренды каждого запуска не реализуются.
Генерация фразы клиентом тоже возможна, если авторизация привязки подтверждается через Telegram. Перемена места генерации не превращает схемы в математически обратные: в обоих случаях доказательство владения связывает две стороны. Здесь короткая фраза — временный код привязки, а дальнейшие запросы используют отдельный случайный ключ.

## Контейнер и проверки

Compose сохраняет сервис `bot`, volume `bot-data` и имя образа.
Сеть `proxy` — Nginx Proxy Manager, `vpn` — Throne; алиасы `partizan-backend` и `partizan-telegram-bot`.
Git-stack Portainer обновляет и Compose, и образ; stack из веб-редактора сам Compose из Git не подхватывает.
Секреты остаются на сервере, не включаются в образ и не выводятся в HTTP-журнал.

```sh
docker build --target test -t partizan-backend:test .
docker run --rm --network none --read-only --tmpfs /tmp:size=16m partizan-backend:test
```

Письма и Telegram API в тестах фиктивные.
